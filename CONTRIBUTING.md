# Contributing to LUFScale

Thank you for your interest in LUFScale.

## Questions and ideas

Use GitHub Discussions for usage questions, feedback and ideas that do not yet describe a specific change to the application.

## Reporting a defect

Before opening an Issue:

1. verify that the problem affects the latest published version;
2. specify the operating system, architecture and package type;
3. provide the exact steps required to reproduce the problem;
4. describe both the observed and expected results;
5. attach useful diagnostic information only after removing paths, filenames and other personal data.

Do not attach copyrighted, personal or confidential audio files to a public Issue.

## Proposing a change

A Pull Request should:

- address a clearly described change;
- avoid mixing functional changes with unrelated cosmetic restructuring;
- preserve license information and third-party notices;
- include or update tests when behavior changes;
- state the platforms on which the change was verified.

Apply platform-specific changes to the corresponding edition. If the same change affects macOS and Windows, compare the two source trees explicitly: they must not be assumed to be identical.
